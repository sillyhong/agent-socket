# 网页历史对话按项目分组设计

## 目标

网页展示 Codex 在所有项目中的未归档历史对话，并按照每条对话的工作目录（`cwd`）分组。用户可以打开历史对话并继续交流。新建对话仍使用当前配置的工作目录。

## 当前行为

后端调用 `thread/list` 时传入 `archived: false`、`cwd: config.cwd` 和 `limit: 100`。因此侧栏只会显示当前配置工作目录下、当前返回页中的未归档对话。线程摘要已经包含 `cwd`，但侧栏目前是平铺列表。

## 选定方案

### 历史数据读取

- 查询未归档对话时不传 `cwd` 筛选条件。
- 使用响应中的 `nextCursor` 请求后续分页，直到 `nextCursor` 为 `null`。
- 每页请求 100 条。
- 保留每条线程原有的完整 `cwd`，并以此作为项目标识。
- 新建线程仍使用 `config.cwd`；打开历史线程时继续使用其线程 ID 和现有恢复流程。
- 对话按 `updatedAt` 从新到旧排序，与当前前端排序方式一致。

### 侧栏分组

- 按完整 `cwd` 分组；不根据 Git 仓库根目录合并嵌套路径。
- 分组标题显示目录名，辅助信息显示完整路径，避免同名目录混淆。
- 项目分组可折叠，默认展开。
- 项目组按照组内最近更新的对话排序；组内对话按照 `updatedAt` 从新到旧排序。
- 保留现有的对话选择、删除和活动会话行为。

### 部分加载失败

- 如果后续分页请求失败，仍显示之前已成功读取的对话，并通过现有提示横幅显示错误。
- 即使历史列表读取失败，已经打开的对话仍可继续使用。
- 历史列表不显示已归档对话。

## 备选方案

1. **按完整工作目录分组（选定）：** 直接使用线程元数据，支持非 Git 目录，无需扫描文件系统。即使目录同名，也会因为完整路径不同而分开显示。
2. **按 Git 仓库根目录分组：** 可合并仓库子目录中的对话，但需要额外解析仓库根目录，且不适用于非 Git 目录。
3. **保留平铺列表并增加项目筛选：** 不需要分组，但不符合按项目展示对话历史的需求。

## 数据流

1. 启动或刷新会话列表时，服务端调用 `thread/list`，传入 `archived: false`，不传 `cwd`，并设置 `limit: 100`。
2. 服务端累积每次响应中的 `data`，并通过 `nextCursor` 继续请求，直到没有下一页。
3. 服务端将累积的标准化会话摘要（包括 `cwd`）发送给网页客户端。
4. 客户端根据完整 `cwd` 对会话分组，并渲染项目分组及其会话列表。
5. 用户选择会话时继续使用现有的 `session.open` 流程；新建会话继续使用 `config.cwd`。

## 错误处理

如果某页请求失败，但此前已有成功读取的页面，则保留并显示已收集的会话，同时通过现有提示横幅报告错误。读取历史列表失败时不得清除当前选中会话的消息。如果第一页就读取失败，则显示错误并保留原有列表状态。

## 验收标准

- 侧栏显示来自多个 `cwd` 的未归档对话。
- 目录名相同但完整路径不同的项目会显示为不同分组。
- 超过 100 条未归档对话时，会通过游标分页完整读取。
- 项目分组和组内对话均按照最近更新时间排序。
- 项目分组可以折叠，且默认展开。
- 打开历史对话后会加载历史消息，并可继续发送消息。
- 新建对话仍属于 `config.cwd`。
- 已归档对话不会显示。
- 后续分页失败时，已读取的会话仍可见，且会显示错误提示。

## 范围

本次变更包括后端历史列表读取和网页侧栏展示。不包括归档历史浏览、项目重命名、仓库根目录发现，以及单独的项目筛选或搜索控件。
