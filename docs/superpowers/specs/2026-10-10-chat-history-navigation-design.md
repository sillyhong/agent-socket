# 网页聊天历史导航优化设计

## 目标

项目与会话列表、长聊天记录同时存在时，提升可读性和定位效率。用户可以收起项目列表，通过用户消息锚点快速定位历史；阅读旧消息时不被新内容强制拉回底部。

## 已选方案

保留单页聊天布局，提供可收起的项目/会话侧栏和聊天历史锚点栏。窄屏时锚点栏改为抽屉，避免挤压聊天内容。

## 布局与交互

- 项目/会话侧栏保持现有分组与折叠行为，增加收起/展开控制；收起后聊天区获得释放的宽度。
- 聊天区与侧栏分别滚动。消息列表继续作为主要阅读区。
- 锚点栏为每条用户消息生成一项，内容取用户消息摘要并限制长度。点击后平滑滚动到对应用户消息卡片。
- 使用消息卡片进入视口的状态高亮当前锚点。快速滚动、连续或长消息时，以视口顶部最近可见的用户消息作为当前项。
- 锚点栏可折叠；窄屏下以按钮打开覆盖式抽屉，选中锚点后关闭抽屉并跳转。
- 切换会话后重置当前会话的锚点状态。没有用户消息时显示空状态，不显示空锚点。

## 滚动行为

- 首次打开会话、切换会话、发送新消息时定位到最新消息。
- 渲染更新时，若用户原本靠近底部，则继续跟随新消息；若用户已向上阅读，则保留视口位置。
- 用户不在底部时出现“回到最新”控件；点击后滚到底部并恢复跟随。
- 锚点跳转时暂停自动跟随，避免与目标位置冲突；用户滚回底部后恢复跟随。

## 组件与数据流

- 页面布局层管理项目侧栏、聊天区、锚点栏的展开状态和窄屏抽屉状态。
- 消息渲染层给每张消息卡片和用户消息卡片添加稳定 DOM 标识。
- 锚点列表从当前会话已加载的用户消息生成；不增加服务端接口或持久化数据。
- `IntersectionObserver` 或等效视口观察逻辑更新当前锚点；锚点点击通过目标 DOM 元素滚动。
- 会话切换时先清理旧观察器，再针对新消息列表建立锚点与观察关系。

## 边界与错误处理

- 用户消息摘要按纯文本生成，复用现有 HTML 转义，不将消息正文作为 HTML 注入。
- 消息卡片重绘或会话切换时释放观察器和事件监听，避免旧节点残留或重复观察。
- 当前只有已加载的完整历史可生成锚点；若以后增加消息分页，需为分页加载补充锚点更新行为。
- 不改项目分组、历史数据读取、会话选择、删除和发送消息协议。

## 验收标准

1. 项目侧栏可收起和展开，聊天区随可用宽度扩展。
2. 长对话中，每条用户消息都有对应锚点，摘要不溢出栏宽。
3. 点击锚点可定位到对应用户消息；滚动时当前锚点随视口变化。
4. 向上阅读时新消息不会强制拉到底；底部状态下仍自动跟随新回复。
5. 离开底部后可见“回到最新”，点击后滚到底并继续跟随。
6. 切换会话后，消息、锚点和高亮均对应新会话，不残留旧状态。
7. 窄屏可通过抽屉访问锚点，关闭后聊天内容可读。
8. 空会话不显示无效锚点；包含特殊字符的用户消息摘要安全显示。

## 验证计划

- 手动验证侧栏收起/展开、窄屏布局、锚点跳转与滚动高亮。
- 验证长对话上滑时的位置保持、底部自动跟随及“回到最新”。
- 验证切换会话、空会话、含特殊字符摘要，以及快速滚动时无旧锚点高亮。
